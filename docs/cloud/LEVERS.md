## Switching at runtime

`kyojin_mlx/flags.py` holds the table above. `flags.set_many({name: value})` checks every pair first, then writes the env variable and the
module attributes the code reads per call, and bumps `flags.GEN`. The compiled decode regions (fuse_layer, DSpark draft) retrace when GEN moves.
The server exposes it, loopback peers only (403 otherwise):

    curl -s localhost:PORT/admin/flags                                   # {"flags": {...value, default, runtime, doc}, "gen": N}
    curl -s -XPOST localhost:PORT/admin/flags -d '{"moefuse": 1, "idx_qblock": 256}'

POST returns 409 while a request is waiting / prefilling / decoding, 400 for an unknown, non-runtime or bad value (nothing is applied then).
After a switch the in-memory prefix cache is dropped (its KV was made by the old kernels); the kv-disk cache is not touched.

Not switchable at runtime (fixed at process start):
- **Engram gate** (`KYOJIN_ENGRAM_GATE`): it sets `MLX_MAX_OPS_PER_BUFFER` / `MLX_MAX_MB_PER_BUFFER`, which MLX reads once when mlx is
  imported. The gate tests its md5 in fresh processes and its speed with a second server started with it ON (served rows
  `engram` and `on+engram`; the resident all-on arm runs with the gate OFF).
- **Residency refresh** (`KYOJIN_RESIDENCY_REFRESH_MS`): MLX reads `MLX_METAL_RESIDENCY_REFRESH_INTERVAL_MS` when the Metal device is built; `kyojin_mlx/__init__` copies it over before mlx is imported.
- **Qwen step regions**: built once at install time.
- **`KYOJIN_VERIFY_REPLAY`**: replays recorded command buffers; a switch would need a new recording.
- Sub-tunings not exposed (env at import only): `KYOJIN_GLUE_FUSE_MIXVEC`, `_MIXARGS`, `_MIXNORM`, `_MIXPRE_OFF`, `KYOJIN_FUSE_MIXPRE`.
